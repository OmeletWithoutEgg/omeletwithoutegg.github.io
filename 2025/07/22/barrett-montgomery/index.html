Barrett Reduction 與 Montgomery Multiplication

對競程有點經驗的人應該都要知道除法是一個很慢1的操作。
不過，如果是除以 2k2^k2k 的話就很簡單了，只要一個 shift 操作就能完成。
Barrett reduction 和 Montgomery multiplication 分別用了不一樣的方法，給定一個正整數 MMM，針對 MMM 做一些預處理之後，我們可以不用任何除法指令，只用較少的乘法、加減法與 shift 來完成「兩個數字相乘之後模 MMM」的操作。

記號的定義

  • 對於兩個整數 u,vu, vu,v，u≡v(modM)u \equiv v \pmod Mu≡v(modM) 的意思是 (u−v)(u - v)(u−v) 是 MMM 的倍數。
  • 對於整數 uuu，u mod Mu \bmod MumodM 是使得 u≡v(modM)u\equiv v \pmod Mu≡v(modM) 且 v∈[0,M)v \in [0, M)v∈[0,M) 的唯一的 vvv。
  • [l,r)[l, r)[l,r) 指的是 l≤x<rl \leq x < rl≤x<r 的所有整數 xxx。
  • 對於一個實數 zzz，⌊z⌋,⌈z⌉,⌊z⌉\lfloor z \rfloor, \lceil z \rceil, \lfloor z \rceil⌊z⌋,⌈z⌉,⌊z⌉ 分別是向下取整、向上取整、四捨五入的意思。

下文假設我們預先知道 MMM，而當要計算 a⋅b mod Ma \cdot b \bmod Ma⋅bmodM 之前都先算好完整的乘積 x=a⋅bx = a \cdot bx=a⋅b，其中 0≤a,b<M0 \leq a, b < M0≤a,b<M 而 0≤x<M20 \leq x < M^20≤x<M2。可以想像 M=998244353M = 998244353M=998244353，於是 a,b,Ma, b, Ma,b,M 可以用一個 int32_t 存，而 xxx 必須要用 64 個 bit，也就是 int64_t。

Barrett reduction

要計算 x mod Mx \bmod MxmodM，可以先計算 q=⌊x/M⌋q = \lfloor x / M \rfloorq=⌊x/M⌋ 之後計算 r=x−q⋅Mr = x - q \cdot Mr=x−q⋅M。

但這樣計算 qqq 我們也需要一次除法指令。試著用一個分數 dR\frac{d}{R}Rd​ 來近似 1M\frac{1}{M}M1​，其中限制 RRR 是一個 222 的冪次 2，因為現代的 CPU 一般使用二進位儲存數字，除以 222 的冪次再取整是一個不用除法指令也可以很快做到的操作。

於是與其計算 qqq，我們改計算

q~=⌊x⋅dR⌋ \tilde{q} = \left\lfloor \frac{x \cdot d}{R} \right\rfloor q~​=⌊Rx⋅d​⌋

如果 ddd 恰好等於 R/MR / MR/M 的話那麼 dR=1M\frac{d}{R} = \frac{1}{M}Rd​=M1​，完全沒有誤差，但 ddd 需要是個整數，所以一般會取 ⌊R/M⌋\lfloor R / M \rfloor⌊R/M⌋ 或 ⌈R/M⌉\lceil R / M \rceil⌈R/M⌉。因為我們事先知道 MMM，所以 ddd 的值可以預處理。

設 dR=1M+ε\frac{d}{R} = \frac{1}{M} + \varepsilonRd​=M1​+ε，則

struct Barrett {
  using u32 = uint32_t;
  using u64 = uint64_t;
  using u128 = __uint128_t;
  u32 M;
  u64 d; // R := 2^{64}; d := floor(R / M)
  Barrett(u32 t_M) : M(t_M), d(-1ULL / t_M) {}
  u32 reduce(u64 x) const { // x % M
    // we need a 128-bit multiplication here to calculate q
    u64 q = (u128(d) * x) >> 64;
    u64 r = x - q * M;
    return r >= M ? r - M : r;
  }
};

取更大的 RRR: 精準除法

再次注意到

q~=⌊xM+x⋅ε⌋ \tilde{q} = \left\lfloor \frac{x}{M} + x \cdot \varepsilon\right\rfloor q~​=⌊Mx​+x⋅ε⌋

Signed 與 Unsigned

世界上存在兩種流派，一種是把 x mod Mx \bmod MxmodM 的值域限制在 [0,M)[0, M)[0,M)，另一種則是限制在 [−M/2,M/2)[-M/2, M/2)[−M/2,M/2)。前者稱為 unsigned 而後者稱為 signed。前述的 Barrett reduction 以及程式碼都是 unsigned 派的，而如果是 signed 版本的話，可以把 floor 改成 round，也就是改算 q~=⌊(x⋅d)/R⌉\tilde{q} = \left\lfloor (x \cdot d) / R \right\rceilq~​=⌊(x⋅d)/R⌉。除了把最外層的 floor 改成 round 或者把 ddd 從 floor 改取 ceil 之類的改動以外，比較一般化的表述可以看英文維基百科。

Montgomery Multiplication

Montgomery multiplication 的思路則跟 Barrett reduction 不太一樣。比起計算 x mod Mx \bmod MxmodM，我們來計算 x⋅R−1 mod Mx \cdot R^{-1} \bmod Mx⋅R−1modM 吧！其中 R−1R^{-1}R−1 是 RRR 在 ZM\mathbb{Z} _ MZM​ 下的模逆元。

如果我們可以找到一個 ℓ\ellℓ 使得 x+ℓ⋅M≡0(modR)x + \ell \cdot M \equiv 0 \pmod Rx+ℓ⋅M≡0(modR) 的話，那麼

y=x+ℓ⋅MR y = \frac{x + \ell \cdot M}{R} y=Rx+ℓ⋅M​


就會是一個整數。也就是說，我們直接（在整數或者實數上）除以 RRR 就可以得到 yyy。不難驗證 y≡x⋅R−1(modM)y \equiv x \cdot R^{-1} \pmod My≡x⋅R−1(modM)。

ℓ\ellℓ 要怎麼找呢？移項一下得到 ℓ⋅M≡−x(modR)\ell \cdot M \equiv -x \pmod Rℓ⋅M≡−x(modR)，不妨取 ℓ=x⋅(−M−1) mod R\ell = x \cdot (-M^{-1}) \bmod Rℓ=x⋅(−M−1)modR，其中 M−1M^{-1}M−1 指的是在 ZR\mathbb{Z} _ RZR​ 下的模逆元。雖然算模逆元需要花一些功夫，不過 (−M−1) mod R(-M^{-1}) \bmod R(−M−1)modR 可以在預處理時計算。

接著來證明一下 yyy 夠小。如果 RRR 取得夠大使得 x<MRx < MRx<MR 的話，則 xR<M\frac{x}{R} < MRx​<M；同時 ℓR<1\frac{\ell}{R} < 1Rℓ​<1，所以

y=x+ℓ⋅MR=xR+ℓR⋅M<M+M<2M y = \frac{x + \ell \cdot M}{R} = \frac{x}{R} + \frac{\ell}{R} \cdot M < M + M < 2M y=Rx+ℓ⋅M​=Rx​+Rℓ​⋅M<M+M<2M

因此，若我們事先得到 MMM 之後做好預處理，那麼計算 x⋅R−1 mod Mx \cdot R^{-1} \bmod Mx⋅R−1modM 只需要一次乘法、一次  mod R\bmod RmodR 的乘法、一次加法、一次除以 RRR，以及一個 conditional subtraction。

定義函數 redc:[0,MR)→[0,M);x↦(x⋅R−1 mod M)\textrm{redc}: [0, MR) \to [0, M); x \mapsto \left(x \cdot R^{-1} \bmod M\right)redc:[0,MR)→[0,M);x↦(x⋅R−1modM)。我們已經知道怎麼快速計算 redc\textrm{redc}redc 了。

缺點

Montgomery multiplication 一個很大的缺點就是需要 R,MR, MR,M 互質，因為需要計算 M−1M^{-1}M−1，而且需要 R−1R^{-1}R−1 的存在。通常來說 RRR 會挑選 222 的冪次，所以 MMM 就只能是奇數。

struct Mont { // Montgomery multiplication
  using u32 = uint32_t;
  using u64 = uint64_t;
  constexpr static int W = 32, logW = 5;
  u32 mod, neg_minv, R1, R2;
  Mont(u32 t_mod) : mod(t_mod) {
    assert(mod % 2 == 1);
    neg_minv = 1;
    for (int j = 0; j < logW; j++)
      neg_minv *= 2 - neg_minv * mod;
    assert(u32(neg_minv * mod) == 1);
    neg_minv = -neg_minv;
    const u64 R = (u64(1) << W) % mod;
    R1 = static_cast<u32>(R);
    R2 = static_cast<u32>(R * R % mod);
  }
  u32 redc(u32 a, u32 b) const {
    u64 x = u64(a) * b;
    u32 l = u32(x) * neg_minv;
    u32 y = (x + u64(l) * mod) >> W;
    return y >= mod ? y - mod : y;
  }
  u32 from(u32 x) const { return redc(x, R2); }
  u32 get(u32 a) const { return redc(a, 1); }
  u32 one() const { return R1; }
};

Barrett Reduction 與 Montgomery Multiplication 的比較

假設模數 MMM 是 www-bit 的，也就是 M<2wM < 2^wM<2w。

方法需要多長的乘法優點缺點
Barrett reduction2w2w2w 乘 2w2w2w概念比較簡單需要比較長的乘法
Montgomery multiplicationwww 乘 www易 vectorize對奇數不能使用、需要改較多程式碼 5

若以 MMM 是 32-bit 來看的話，Barrett reduction 需要用到 __uint128_t 的乘法：兩個 64-bit 的數字乘出 128-bit 的結果，對應的組合語言是 mul 這個 instruction。但 Montgomery 可以全部在 uint64_t 內做完。而若 MMM 是 64-bit 的話，Barrett 都需要手寫 256-bit 乘法了，Montgomery 可以用 __uint128_t 做。Montgomery multiplication 所需乘法比較短，更容易 vectorize (SIMD)。

除了 Barrett reduction 和 Montgomery multiplication 以外當然還有其他演算法，例如 div2by1，但本篇不打算介紹。另外，英文維基也有寫到，在某種觀點下 Barrett reduction 和 Montgomery multiplication 是一樣的，這也有在後量子密碼學的課上提到。
